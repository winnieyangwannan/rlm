You are an expert ML engineer analyzing the diversity of code solutions generated by LLMs for a Kaggle competition. You will be given N solution summaries, each following a structured format covering: Data Preprocessing, Feature Engineering, Model Selection, Training Methodology, Evaluation & Submission, and Notable Implementation Details.

Your task is to assess the **diversity** of these solutions along multiple axes and produce a structured analysis.

## Axes of Diversity

For each axis below, identify the distinct "clusters" of approaches, count how many solutions fall into each, and flag any approaches that are unique (appear only once).

1. **Model Architecture Diversity**: What model families/architectures are used? (e.g., FasterRCNN, YOLO, DETR, EfficientDet, ensemble vs single)
2. **Backbone Diversity**: What backbones/pretrained weights are used? (e.g., ResNet50, ResNet101, Swin, ConvNeXt)
3. **Preprocessing Pipeline Diversity**: What are the distinct preprocessing strategies? (e.g., image size, normalization, CLAHE, DICOM handling variations)
4. **Augmentation Diversity**: What augmentation strategies are used? (e.g., none, basic flips, heavy augmentation, mosaic, mixup)
5. **Training Recipe Diversity**: What are the distinct optimizer/scheduler/loss/regularization combinations?
6. **Post-processing Diversity**: What post-processing strategies are used? (e.g., NMS variants, WBF, TTA, confidence calibration)
7. **Ensemble Strategy Diversity**: Are ensembles used? What types? (e.g., none, model ensemble, multi-scale, snapshot)
8. **Validation Strategy Diversity**: What validation schemes are used? (e.g., holdout, k-fold, stratification method)

## Output Format

```json
    }

  "most_diverse_axis": "...",

    // pairs of solution IDs that are near-duplicates across ALL axes
    [<id_a>, <id_b>, "<brief justification>"]
  ],

    "..."
  ]
}
```

## Guidelines
- Be precise: two solutions using the same model family but different backbones are diverse on the backbone axis but not the architecture axis.
- For entropy calculation: use H = -Σ p_i log2(p_i) / log2(k) where k = number of distinct approaches and p_i = fraction of solutions in approach i. If k=1, entropy=0.
- "Gaps" should reflect reasonable alternatives a skilled practitioner might try, not exotic or impractical ideas.
- When in doubt, treat minor hyperparameter differences (e.g., lr=0.003 vs lr=0.005 with the same optimizer) as the SAME approach, but major structural differences (e.g., SGD vs AdamW, StepLR vs CosineAnnealing) as DIFFERENT approaches.
